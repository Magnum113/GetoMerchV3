# GetoMerch — учёт мерча

Веб-приложение для управления складом футболок и худи с принтами и вышивкой. Next.js 15 + Supabase + shadcn/ui.

## Возможности

- **Каталог SKU** — уникальные комбинации (категория × ткань × цвет × размер × дизайн × тип украшения). SKU создаются автоматически.
- **Склады** — учёт остатков на нескольких складах (свой склад + цех вышивки).
- **Заказы в цех** — отправка пустых товаров на вышивку. При смене статуса на «отправлено» система автоматически перемещает товары со своего склада в цех (если в цехе их недостаточно). При статусе «получено» — автоматически создаются готовые SKU и возвращаются на свой склад.
- **Производство принтов** — нанесение принта превращает пустой товар в готовый.
- **Журнал операций** — полная история всех движений: приёмки, перемещения, продажи, производство, корректировки, списания.
- **Дизайны** — каталог дизайнов с превью.
- **Справочники** — управление складами, цветами, размерами.
- **Дашборд** — KPI, остатки по складам, активные заказы, last-actions, низкие остатки.

## Структура БД

12 таблиц с префиксом `merch_`:

- `merch_warehouses` — склады (own / workshop)
- `merch_product_categories` — категории (футболка, худи)
- `merch_fabric_types` — типы ткани (обычная, варёнка)
- `merch_colors` — цвета (с HEX)
- `merch_sizes` — размеры
- `merch_designs` — дизайны
- `merch_decoration_types` — типы украшения (принт / вышивка)
- `merch_products` — SKU (уникальные комбинации)
- `merch_inventory` — остатки на складах
- `merch_workshop_orders` — заказы в цех
- `merch_workshop_order_items` — позиции заказов
- `merch_transactions` — журнал операций

## Конфигурация

Файл `.env.local` уже создан с публичным ключом Supabase. Если нужно подключить другой проект, поменяй в нём:

```
NEXT_PUBLIC_SUPABASE_URL=https://<ref>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<publishable_key>
```

## Бизнес-логика заказов в цех

Жизненный цикл заказа: `pending` → `sent` → `in_progress` → `ready` → `received`.

- **Отправлено в цех** — если у тебя на складе есть пустые товары, а в цехе их недостаточно, система автоматически создаст транзакцию перемещения «свой склад → цех».
- **Получено** — для каждой позиции заказа:
  1. Находится / создаётся готовый SKU (пустой + дизайн + тип украшения)
  2. На складе цеха создаётся транзакция «производство»: пустые −N, готовые +N
  3. Готовые товары перемещаются «цех → свой склад»
