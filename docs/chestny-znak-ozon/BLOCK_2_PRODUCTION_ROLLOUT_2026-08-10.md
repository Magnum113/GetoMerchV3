# Блок 2: production schema и infrastructure rollout

Дата выполнения: 10 августа 2026 года.

## Результат

Блок 2 завершен. В production развернуты внутренние таблицы, read model и
инфраструктура интеграции «Честного знака». Внешние операции маркировки не
включались: система остается в fail-closed режиме до отдельных canary-ворот.

## База данных

- source of truth: локальная PostgreSQL `getomerch_production` на VPS;
- применены forward-only миграции `0005`-`0018`;
- итоговая schema version: `0018`;
- production backup/restore процедуры проверены до rollout;
- после rollout создана зашифрованная копия
  `getomerch-database-backup-20260810T110728Z.tar.gz.gpg`;
- off-site загрузка последней копии завершилась успешно;
- backup зафиксировал 63 прикладные таблицы;
- временные базы `getomerch_stage12_block2`, `getomerch_stage13_block2` и
  `getomerch_stage13_block2_base` удалены после проверок.

## Runtime

- production release: `20260810T104454Z-admin-285f9da40069`;
- `getomerch-admin.service` активен;
- изолированный `getomerch-marking-worker.service` активен и включен в
  автозапуск;
- `getomerch-marking-import-scrub.timer` включен и выполняется по расписанию;
- marking keyring и agent credentials находятся в root-only файлах на VPS;
- публичный broker endpoint для outbound-only Mac signer развернут через
  production nginx;
- секреты не передаются в клиентский bundle, Git или документацию.

После отдельного rollout этапа 9 включены только общий marking-контур, signer
и read-only ГИС МТ в sandbox. Все feature flags для ГИС МТ/SUZ/Ozon write,
ввода, вывода, возвратов и automation оставлены выключенными. Наличие worker и
endpoint не дает разрешения на внешнюю запись без явного canary-включения
конкретного флага. Результат этапа 9:
[`stage-9/PRODUCTION_CANARY_2026-08-10.md`](stage-9/PRODUCTION_CANARY_2026-08-10.md).
