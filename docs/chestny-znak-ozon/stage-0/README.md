## Важные выводы

1. Для легкой промышленности в СУЗ используется `productGroup=lp`,
   `releaseMethodType=PRODUCTION` и `templateId=10`.
2. При выдаче КМ для `lp` СУЗ автоматически формирует отчет о нанесении.
   Отдельный `POST /api/v3/utilisation` для футболок не нужен.
3. Ввод в оборот собственного производства является отдельным документом
   `LP_INTRODUCE_GOODS` через True API.
4. Статус документа прямой подачи нужно читать через
   `GET /api/v4/true-api/doc/{docId}/info`. Метод
   `/doc/validator/status` документирован для проверки УПД/УПДи и не является
   штатным poll endpoint для `LP_INTRODUCE_GOODS`.
5. Для дистанционного вывода используется `LK_RECEIPT` с
   `action=DISTANCE`. Для возврата целого кода в оборот используется
   `LP_RETURN` с `return_type=REMOTE_SALE_RETURN`.
6. Переписка со службой поддержки не используется как требование,
   доказательство или production gate.
7. Уточнение по результату canary 14 августа 2026 года: отсутствие РД не
   блокирует readiness, заказ КМ, печать и нанесение, но вид, номер и дата РД
   обязательны перед `LP_INTRODUCE_GOODS`.

  появлении первого такого заказа.

  FBS-возврата в FBO; это блокирует автоматизацию этапа возвратов, но не этап 0.

  дистанционного вывода; они нужны на этапах аутентификации и вывода, являются
  runtime configuration и не должны попадать в Git.
