# Оптимизация аналитики: этапы 2–3

Дата реализации: 2026-09-10.

## Цель

Ускорить открытие и переключение периодов на дашборде без удаления показателей, сокращения истории или изменения финансовых формул.

## Этап 2. Единый серверный запрос

- Добавлен защищённый endpoint `GET /api/admin/analytics/dashboard`.
- Браузер передаёт границы выбранного периода одним запросом.
- Сервер параллельно читает заказы Ozon, финансовые операции, ручные расходы, справочники, SKU-сопоставления и остатки.
- Сервер продолжает читать все страницы каждого источника. Скрытого ограничения первой страницей нет: при достижении защитного предела запрос завершается ошибкой, а не показывает неполные цифры.
- Endpoint принимает период не более 370 дней. Для расчёта сравнений сервер дополнительно загружает полный предыдущий период такой же длины.
- В ответе `Server-Timing` отдельно указывает время чтения базы и расчёта.

До этапа 2 браузер выполнял восемь независимых семейств запросов, включая последовательную пагинацию. Теперь сетевой контракт дашборда состоит из одного запроса.

## Этап 3. Серверная подготовка данных

- Все существующие формулы вынесены в общий чистый модуль `src/lib/analytics-dashboard.ts` и выполняются на VPS.
- В браузер больше не передаются полные массивы заказов, финансовых операций, расходов, SKU-сопоставлений и остатков.
- Endpoint возвращает только готовые KPI, ряды графиков, структуру расходов, статистику заказов и невыкупа, топ товаров и агрегированную стоимость остатков.
- Сервер заранее формирует ряды для шагов `день`, `неделя` и `месяц`. Поэтому переключение шага остаётся мгновенным и не вызывает новый запрос.
- Во время обновления старый полный снимок остаётся на экране до успешного получения нового.
- Ответ помечен `Cache-Control: private, no-store`: после синхронизации пользователь видит актуальные данные, а не устаревший промежуточный кэш.

## Гарантия полноты и совместимости

Команда `npm run check:analytics-baseline` теперь дополнительно строит новый серверный снимок и сравнивает его с прежним клиентским результатом. Проверяются:

- пять периодов: 7, 30 и 90 дней, текущий месяц и текущий год;
- три шага: день, неделя и месяц;
- KPI и предыдущий период;
- все графики заказов, выручки и невыкупа;
- структура расходов;
- топ товаров по прибыли и невыкупу;
- стоимость остатков по складам.

Это проверка равенства результата, а не приблизительное сравнение.

## Эксплуатационная проверка

После production-деплоя необходимо проверить:

1. Endpoint отвечает `200` для периода 30 дней и текущего года.
2. В `sourceCounts` присутствуют все строки источников, использованные в расчёте.
3. Размер JSON существенно меньше прежней выгрузки сырых данных.
4. Переключение периода сохраняет старые данные до завершения обновления.
5. Переключение шага не создаёт нового сетевого запроса.
6. Значения основных KPI совпадают с контрольным снимком до оптимизации.
